## 2026-09-07

- **Scope.** Build from scratch. Nothing pre-existing except the Vite scaffold in `web/` and the research dossier.
- **Framing.** Inspection targeting, not culprit attribution. The system produces leads; MARPOL enforcement confirms by oil sample match on board. Cite SkyTruth Cerulean as prior art ourselves.
- **Roles.** Two only: `admin` and `officer`. Viewer role dropped. No public signup; admin provisions accounts.
- **Auth.** Self-built. bcrypt cost 12, HS256 JWT, 12 h expiry, localStorage, Bearer header. slowapi rate limit on login. Refresh tokens and OTP deferred.
- **Python.** 3.13 for backend and ML. 3.14 rejected because opencv, rasterio and onnxruntime wheels lag.
- **Model serving.** ONNX + onnxruntime in the API container. PyTorch only for training (Colab T4).
- **Model.** Custom U-Net, 5 classes (sea, oil, look-alike, ship, land), trained on Krestenitis et al. 2019. Class-weighted CE + Dice. Report per-class IoU on the 110-image test split.
- **Fallback.** OpenCV dark-spot heuristic when the model is unavailable. Always labelled `engine: "heuristic"` in API and UI.
- **Map.** Cesium for the app globe. `cobe` kept for the landing hero only.
- **Database.** MongoDB Atlas M0 with GeoJSON + 2dsphere. PostGIS considered and rejected for free tier and document flexibility.
- **Drift.** First-order Lagrangian backtrack: current + 3 % wind, Open-Meteo Marine + Forecast, three origin ellipses at t-6h, t-12h, t-24h. OpenDrift is the stated upgrade path.
- **AIS.** AISStream live feed is real. Historical tracks for the demo incident are a generated scenario, labelled as such.
- **Ranking.** Eight weighted features, 0 to 100 score, tiers: prime suspect ≥ 65, person of interest 35 to 64, cleared < 35. Weights in one config file.
- **Hosting.** Vercel (web), Render Docker (API + ML), MongoDB Atlas.
- **Frontend folder** stays named `web/` (the scaffold's name) rather than `frontend/`.
- **Repo** is the source of truth so work continues across Claude accounts and teammates' machines.

## 2026-09-07 (later)

- **Officers are assigned to watch zones.** Users carry `region` (one of ICG West / North-West / East / North-East / A&N) and `zone_ids[]`. Watch zones carry `region`. Admin sets both when creating an officer and can change them later, including zones outside the officer's home region for temporary postings.
- **Assignment is a workload filter, not a permission wall.** Alerts, "my zones" default in the zone selector, and "my cases" use it. Every officer can read every incident nationally. Admin vs officer remains the only hard permission boundary.
- **Incident ownership.** An incident is owned by the officer who confirmed it. Admin can reassign. Others in the region can add notes.
- **Detection verification step.** Before an incident exists the officer must tag the detection: confirm as oil spill (opens the incident), dismiss as look-alike (reason: wind shadow, algal bloom, rain cell, low wind, other), or mark uncertain (second-opinion queue). Every tag is stored with the tile as a training label for the Indian-waters look-alike model.
- **Verification signals shown on the console.** Look-alike vs oil pixel share, wind speed at acquisition (flag < 3 m/s), previous-scene toggle for the same tile, distance to nearest shipping lane and nearest AIS vessel, polygon length-to-width ratio (> 4:1 reads as a discharge trail).
- **Model selection.** Train three candidates on the same loader, loss and 256 px tiles: (1) custom U-Net from scratch in our own code, (2) U-Net with a pretrained ResNet-34 encoder via segmentation_models_pytorch, (3) DeepLabV3+ with a pretrained ResNet-50 encoder. Score all three on the 110-image Krestenitis test split (per-class IoU, mIoU, params, CPU inference ms). The best mIoU with acceptable CPU latency is exported to ONNX and served; the other two stay as rows in `ml/metrics.json` and appear in the comparison table on the Detection Console and in the report. Only one model runs in production. If time is short, train (1) and (2) first; (3) can be added later without touching the app.
- **Quality bar.** Production grade throughout: typed schemas, tests, env-driven config, Docker, CI green, no demo-only shortcuts left in code paths that ship. Build one component at a time to "done when" acceptance.
- **Detection upgrades (weeks 3 to 4).** (1) Ship-at-slick-head: ship-class pixels at the head of an elongated slick are geolocated and matched to the nearest AIS position at acquisition; a match adds a top-weighted ranking feature, no match flags a dark vessel. (2) Context filters shown as lines in the result panel: wind < 3 m/s at acquisition, downwind of coast within a few km (Natural Earth coastline), same patch present on previous pass, no AIS traffic within 30 km in 24 h. (3) Uncertainty overlay from softmax entropy. Whole-scene inference uses 256 px tiles with 32 px overlap and test-time augmentation; dB calibration and speckle filter identical in training and serving. Volume estimate via Bonn Agreement thickness codes shown as a caveated range. Roadmap: EOS-04 / NISAR tiles, dual-pol once Indian labels exist.
- **Incident upgrades (weeks 6 to 7).** (1) Close-out outcome (confirmed by sample / boarded and cleared / not boarded) stored per incident and used to report tier precision and re-fit weights. (2) Intercept card for the top suspect: projected positions at +6/+12/+24 h, next port and ETA, pre-filled Port State Control request. (3) Multi-scene linking: a new detection overlapping an open incident's drifted position attaches to it; incident shows slick evolution and drift-prediction error. Roadmap: probabilistic drift cloud, versioned ranking, repeat-offender view, alerts with escalation, officer overrides with reasons, GeoJSON/KML export.
- **Health `model` field** reports `unet` when an ONNX file is present, otherwise `heuristic` (the fallback is always available, so "missing" was misleading). The console shows which engine answered on every result.
- **Sample tiles** are synthetic, watermarked placeholders until real Sentinel-1 tiles are exported from Copernicus Browser. They carry `synthetic: true` and the UI labels them. Never present them as imagery.
- **Drift + ranking implemented as designed.** Weather from Open-Meteo forecast/archive + marine endpoints; unreachable service degrades to a climatological fallback flagged `weather_source: fallback` and shown in the UI. Ranking reads `ais_positions` (live or scenario, indistinguishable), interpolates tracks at 5-minute steps so dark segments still register spatial/temporal fit, and evaluates each zone in a time window of ±max(1.5 h, 0.35 × hours_before). Candidate cut-off is 2.5 ellipse radii.
- **Seed runs the real pipeline.** The demo incident is no longer hand-inserted. `scripts/seed_db.py` segments the bundled tile, fetches the real weather for the acquisition night, backtracks the origin zones, lays the scenario ship tracks around those zones (guilty tanker through the t-12h zone on the slick axis, gap 12.6→11.9 h before acquisition), and calls the same `create_incident` service the API uses. Reason: with real weather the drift went east, not south-west as the hand-written tracks assumed, and the pipeline honestly found zero candidates. Tracks relative to computed zones keep the demo consistent on any date.

## 2026-09-07 (evening)

- **`cobe` is now used on the Dashboard too, not just the landing hero.** This supersedes the earlier "cobe kept for the landing hero only" line. The Dashboard gains a "Where the slicks are" panel: a dark interactive globe with one clickable dot per incident, coloured by the leading candidate's tier (prime = red, person of interest = amber, not ranked = teal) and sized by slick area. Clicking a dot selects that locality and flies the globe to centre it; the pane beside it shows zone, area, confidence, detection time, centroid to 4 dp, ships in zone now, and the leading candidate, with a link into the investigation. Selection is two-way: a crosshair button on each row of "Open incidents" selects the same slick on the globe. Cesium remains the decision for the full app map (Live Map), where real basemap imagery, drift ellipses and AIS tracks are needed; cobe is the at-a-glance national picture, which is a different job and much cheaper.
- **Marker screen positions are read from cobe's own anchor divs.** cobe v2 appends a 1 px anchor div per `id`-bearing marker to the wrapper it injects around the canvas, carrying `left`/`top` as percentages. Reading those is exact and avoids re-deriving its projection. Only front/back visibility is computed locally (camera-space z sign, which needs no calibration). The component therefore renders real `<button>` markers rather than relying on CSS Anchor Positioning, which is Chromium-only and cannot receive clicks.
- **Globe rebuilds are gated on a marker content signature, not array identity.** TanStack Query returns a fresh array on every refetch; `createGlobe` at 22 000 map samples is expensive, and cobe's `destroy()` removes its anchor divs but *not* the wrapper div it injects, so rebuilding on every refetch would nest wrappers indefinitely. The effect keys on a signature of marker id/location/size/colour, live data reaches the render loop through a ref, and teardown unwraps cobe's wrapper.

## 2026-09-08

- **Model bake-off expanded from three candidates to five.** Supersedes the "Model selection" entry of 2026-09-07 (which listed custom U-Net, U-Net+ResNet-34, DeepLabV3+ ResNet-50). Reason: evaluator feedback asking for a broader search over pre-existing, pretrained architectures. The five, all trained under one shared harness (same Krestenitis loader, class-weighted CE+Dice, 256 px tiles, 40 epochs, identical eval — `ml/train.py`):
  1. `unet_scratch` — our custom U-Net (`ml/unet.py`), no transfer learning; the baseline that shows what the pretrained encoders buy.
  2. `unet_resnet34` — U-Net + ImageNet ResNet-34. Direct parity with SkyTruth Cerulean's production model (research.md §3.1).
  3. `unetpp_resnet34` — U-Net++ (nested dense skips) + ResNet-34. Targets thin-slick/boundary recovery.
  4. `deeplabv3p_resnet50` — DeepLabV3+ + ResNet-50. The Krestenitis 2019 / Zhang winning family; ASPP multi-scale context.
  5. `fpn_effb3` — FPN + EfficientNet-B3. Best accuracy-per-MB; the candidate that fits the <400 MB / CPU-latency serving budget.
  Candidates 2–5 come from `segmentation_models_pytorch` with `in_channels=1` (first conv adapted from RGB weights). Scored on per-class IoU, mIoU, params and CPU ms; only the best mIoU within the CPU-latency budget is exported to ONNX and served (`ml/export.py`), the other four stay as rows in `ml/metrics.json` and show in the Detection Console + report. If time is short, train the priority pair (1) and (2) first; the rest can be added without touching the app.
- **Training deps stay out of the backend image.** `ml/requirements-train.txt` (torch, segmentation-models-pytorch, timm) is Colab/training-only; the API serves the ONNX export via onnxruntime, preserving the Render <400 MB budget. Reinforces the 2026-09-07 "Model serving" decision.
- **Preprocessing parity is a hard rule.** `ml/dataset.py` normalises training tiles with the same `mean`/`std` that `ml/export.py` writes into the ONNX sidecar and that `ml/preprocess.normalise_for_model` applies at serving. Default 0.5 / 0.25; change in one place only.

- **Live Map is no longer a page; the map lives inside the incident.** Supersedes "Cesium for the app map (Live Map)" (2026-09-07) and the Live Map / Map view entries that followed. The standalone `/app/map` route and its nav button are gone, and with them the flaw that it hardcoded "the first open incident" because it had no idea which case you came from. The full map — slick, backtracked drift ellipses, every ranked vessel at the replay instant with its trajectory, the selected track highlighted, replay slider, layer toggles — is `web/src/components/IncidentMap.tsx`, opened from the Investigation page's "Open the map" button and expanding in place of the case-file panels. Reason: none of that data exists for an unconfirmed detection (no drift, no ranked ships), so an incident is the natural unit; and selection is now one thing shared with "Ranked vessels" via `useUi`, not two screens showing the same data. Real satellite (Esri) is the default view; the offline plan view stays one click away for a dead-WiFi demo. **Vessels stays in the nav** — it is the national live-AIS list, not an incident view, and its rows no longer link to a map page.

- **One page transition, owned by the two pages it joins.** Dashboard "Open investigation" → Investigation is the only animated route change in the console, modelled on the reference: a near-black (`#0b0501`) blade wipes in from the left over the Dashboard, the destination title (the incident code, exactly as the case-file header shows it) rises into the centre in a serif, holds, then the blade continues off to the right to reveal the case file already rendered underneath. `web/src/components/CaseFileCurtain.tsx` has two modes: the Dashboard renders `cover` and navigates once the screen is dark and the title has settled, passing the title in history state; Investigation renders `reveal` on its first paint whenever that state is present, so Page B never flashes, and clears the state when done so back/forward/refresh show the page plainly. The Dashboard preloads the Investigation chunk on click so the curtain is continuous across the route swap. Replaces the earlier app-wide `PageCurtain` + Zustand store mounted in `AppShell` (2026-09-08, five coloured panels): there is deliberately no global transition system, and no other route animates.

- **Real live AIS, recorded by a standalone process, kept separate from the demo scenario.** `backend/scripts/ais_collector.py` subscribes to AISStream over a WebSocket and writes real vessel reports into `vessels` and `ais_positions`. It runs as its own process rather than inside the API, because its entire value is the hours of data it accumulates and it must survive `uvicorn --reload` and any API restart. Bounding boxes are derived from the `watch_zones` documents, so the recorder and the app cannot disagree about what is inside a zone. Everything it writes carries `source: "live"`; the seeded demo data keeps `source: "scenario"`. Nothing blends the two: the incident pipeline still ranks against the scenario tracks, the Vessels page shows both with a per-row `live` or `demo` chip and a count in the page description. Reason: AIS is a live firehose with no archive, so it can make the vessel list genuinely real today but cannot retroactively supply the pre-spill history that attribution needs. Claiming otherwise would be dishonest, so the UI states the split. Live positions already had a 7-day TTL index, so the collection cannot grow without bound. Adds `websockets` to `backend/requirements.txt`.

- **AISStream has no receiver coverage over Indian waters, so the live-AIS demo beat cannot be Indian.** Measured 2026-09-08 over 60 s on the free feed: 7,962 position reports worldwide, of which northern Europe 4,458, Mediterranean 1,068, US east+Gulf 688, east Asia 155, Singapore/Malacca 51, and **India west 0, India south 0, India east 2**. The key is valid and the socket is fine; AISStream is fed by community terrestrial receivers and India has almost none. Consequence: `scripts/ais_collector.py` gains `--bbox S,W,N,E` (repeatable) so the recorder can be pointed at water that actually has receivers, with the watch zones still the default. The honest demo framing is that live ingestion is proven on real traffic from a covered region while the Indian case stays a reconstructed scenario, both labelled in the UI. Do not claim a live Indian feed. In deployment the Coast Guard's own coastal AIS network supplies the same message types and the collector is unchanged.

- **Two officers, two sectors: live AIS and the Indian scenario shown side by side, never mixed.** Adds a fourth watch zone `z-nsc` "Dover Strait" (the busiest lane in the world, and a real oil-discharge enforcement area under the Bonn Agreement) and a second officer `officer.eu@sagarnetra.in` assigned only to it. The Indian officer keeps all three Indian zones. Reason: AISStream has receiver coverage there and effectively none off India, so this is the only sector where live recording produces ships; keeping it as its own zone with its own officer means real European traffic never appears inside an Indian sector. Deliberately the Dover Strait and not the whole North Sea, because a basin-sized box returned 5,633 vessels, which is a database dump rather than a sector an officer could work.
- **Zone scoping is now enforced server-side, not just stored.** `zone_ids` existed on the user and was settable by an admin, but no read endpoint used it, so every officer saw everything. `app/services/sectors.zone_filter` now scopes `/api/overview` (zones, incidents, KPIs), `/api/incidents` and `/api/vessels/live`; an admin, and an officer with no zones assigned, still sees everything. Seeded scenario vessels and positions are stamped with the incident's `zone_id` so they are filtered by exactly the same rule as live ones, with no special case. The seed also reconciles `zone_ids`/`region` on accounts that already exist, since a stale sector list now silently hides part of an officer's sector; passwords are never touched. `Region` gains `"Europe"` for the liaison account.
- **A live vessel is "in the sector" only while recently heard.** `/api/vessels/live` and the `vessels_tracked` KPI share one filter: the officer's zones, and for `source: "live"` ships a 2-hour last-report window. Seeded scenario ships are exempt, being a fixed reconstruction of one night. Without the window a long recording turns the sector list into a history of everything that ever transited, and the KPI disagreed with the capped list (5,633 against 2,000), which is the kind of mismatch a jury notices.

- **The curtain is now every console page transition, not one pair.** Supersedes the 2026-09-08 "one page transition, owned by the two pages it joins" entry, at the user's request. `App.tsx` renders `<Routes location={display}>` against a location deliberately held one step behind the real one: when the address changes the outgoing page stays on screen while the curtain closes, `display` catches up only once the screen is fully dark, and the destination is revealed already mounted. Pinning the router rather than intercepting clicks means nav tabs, in-page links, programmatic `navigate()`, redirects and the browser back button all animate identically with no page opting in, and no page can flash. The state adjustment happens during render, not in an effect, because an effect paints one frame of the destination first, which is the flash this exists to prevent. Only console-to-console moves animate; the landing page and login are excluded, and a change of query string or hash is not a page change. `web/src/lib/routeTitle.ts` resolves the destination's own title, reading the incident code out of the TanStack Query cache so a case file announces `INC-2026-007` rather than a generic word. `CaseFileCurtain.tsx` is renamed back to `PageCurtain.tsx`, and the per-page cover/reveal wiring is gone from Dashboard and Investigation. Cost: about 2.2 s per navigation, which is deliberate and was flagged.

- **A report is an immutable, revisioned snapshot, and the PDF is the browser's.** `app/services/reports.py` freezes an incident's numbers at export; `app/routers/reports.py` records the export, bumps the revision, and writes a line into both the incident timeline and the audit log. A report is deliberately not a live view: re-ranking or closing a case later must not silently rewrite a document already filed, so each export is a new revision and the print view compares its snapshot against the incident as it stands and warns when they differ. The rendered document is `web/src/pages/ReportPrint.tsx`, an A4 page outside `AppShell` and outside the page-transition curtain, saved through the browser's own print dialog. Reason: no server-side PDF library, nothing to install, works with the network off, and the layout is the same code as the rest of the console. Reports carry `zone_id` so the sector filter applies without a join, and exporting a case outside your sector is refused. The seed no longer carries hand-authored report fixtures that referenced deleted incidents; it exports a real pack from the real demo incident through the same service, so a seeded pack and an officer's pack cannot drift apart. Fixes a seeding bug where `seed_accounts` returned whichever officer it created last, quietly attributing the Gujarat demo case to the North Sea liaison.

- **Zooming the map all the way out hands back to the globe.** A flat Web Mercator map has nothing sensible to show once the whole world fits inside the panel: the tile pyramid is smaller than its container, so Leaflet repeats the earth sideways and pads the poles with grey. `RealMap` therefore sets `minZoom: 3` (the floor where the world still fills a panel), `noWrap` on both tile layers, and `maxBounds` at the Mercator limit with full viscosity, so that state is unreachable by zooming *or* panning. On the Dashboard, reaching the floor fires `onZoomOut`, which reverses the globe→map dive: asking for the whole earth is the globe's job, and the dashboard already had one. `onZoomOut` is optional, so the incident map simply stops at the floor.

- **Every recorded spill has an outline, and the map frames it.** Only the pipeline-built demo incident had a polygon; the nine catalogue records carried an area and a centroid but no shape, so selecting one drew a bare dot next to a stated "0.70 km²" — which reads as *nothing was found*. `slick_polygon()` in `scripts/demo_scenario.py` (mirrored as `slickPolygon()` in `web/src/lib/mock/data.ts` so both modes agree) derives an outline from the numbers the record already carries: an elongated 5.5:1 bilge shape on the record's own long-axis bearing, rippled deterministically, then rescaled so the drawn polygon's area equals the stated area exactly. Nothing is invented beyond what the record states. Three rendering fixes went with it: the dashboard framed a fixed ±0.15° box regardless of slick size, so a small slick was a speck — it now frames the slick's own extent, and `FitBounds` refits when the geometry arrives, because Leaflet reads `bounds` only at construction and the incident detail resolves after the map mounts. The fit is capped at zoom 12 so a small slick keeps its coastline for context. The centroid pin became a hollow ring whenever an outline exists, since it was sitting on top of the thing it points at. And the slick gained an accent hairline outside the multiply pane: the sheen is honest but dark-on-dark, and the edge has to be findable.

- **The sign-in backdrop is water drawn in code, with a video slot left open.** `web/src/components/SeaBackdrop.tsx` paints a hazy harbour sea on a canvas: a horizon with haze and a suggested far shore, and crests placed by deterministic hash noise on quadratically spaced rows, so the surface has perspective and drifts under a slow swell. It also renders a `<video>` that fades in over the top if `web/public/media/login.{webm,mp4}` exists, and stays invisible when the request 404s. Drawn water is the default rather than a stopgap: a bundled clip is megabytes in a repo with no git-lfs, and the build plan requires the demo to survive the venue WiFi dying, so the page has to look right with no asset at all. Motion stops when the tab is hidden and never starts under `prefers-reduced-motion`. The sign-in form moved onto a translucent panel so every field keeps the contrast it had, and the page scrim spans the full width rather than the left grid column, which was leaving a hard vertical seam down the middle of the sea.

- **The sign-in backdrop is the sector itself: Esri imagery of the Chennai–Ennore coast, bundled.** Supersedes the drawn-water entry above, at the user's request. `scripts/stitch_login_bg.py` pulls the same Esri World Imagery tiles the console's maps use for 80.12–80.62 E, 12.94–13.34 N at zoom 13, stitches them, and grades the result down to a 140 kB JPEG at `web/public/media/login.jpg`. Bundled rather than fetched, because the demo has to survive the venue WiFi dying. The blur is not only depth of field: Esri mosaics captures of different dates along this coast and the joins show as rectangular tonal steps, which softening buries. Esri's credit is rendered bottom-right, as their licence requires. `SeaBackdrop` now layers still over clip over canvas — the drawn sea stays underneath as the guarantee that the page can never come up blank, and a clip dropped at `public/media/login.{webm,mp4}` still takes over. Not the user's own screenshot: that was a capture of the app's map panel with the basemap toggle, scale bar, marker dots and Leaflet credit baked into the pixels.

- **The sign-in backdrop grade lives in CSS, not baked into the file.** `SeaBackdrop` applies `saturate(0.8) brightness(0.58) contrast(0.95)` to the backdrop `<img>`, so replacing `web/public/media/login.jpg` with any other photo is a genuine drop-in: it gets the same treatment and the sign-in panel stays readable without anyone re-grading an asset. The bundled Chennai still is now blurred only, which is the part specific to it (it hides Esri's mosaic joins). - **Backdrop photos are fitted whole, not cropped, and the credit tracks the image.** `scripts/fit_login_bg.py` scales any photo to *fit* a 16:9 frame and fills the leftover margin with a blurred enlarged copy of itself, because cropping a 5:4 aerial to a wide page throws away a third of the frame, usually including the vessel. `BACKDROP_CREDIT` in `Login.tsx` is now a single constant rendered only when non-empty: the previous hardcoded Esri line stayed on screen after the backdrop was replaced with a photograph, and a false credit is worse than none.

- **The admin console can now actually provision officers and assign sectors.** The backend already had every endpoint (create user with a generated temporary password, patch role/region/`zone_ids`/active, reset password, create zone); the Admin page was 85 lines of read-only tables whose "New user", "Reset password" and "Disable" buttons did nothing. It now creates officers, assigns and reassigns sectors, resets passwords, enables and disables accounts, and creates sectors from a bounding box. The Officers table shows each officer's sectors by name, and the Sectors tab shows which officers cover each one, including an explicit warning when a sector has nobody watching it. Sector creation is a bounding box rather than a drawn polygon: four numbers need no map editor, and the backend accepts any GeoJSON Polygon when a drawing tool arrives.
- **An officer with no sectors is unscoped, not blocked, and the UI now says so.** `zone_filter` treats an empty `zone_ids` as "no filter" — indistinguishable from an admin — so a newly created officer with no sectors would silently see every zone. Rather than change the filter's meaning late in the build (it is what makes admin work), the Officers table flags such an account `unscoped` in warning colours, the create form requires at least one sector for the officer role, and the sectors dialog warns before saving an empty list. Worth revisiting: the safer default is that an officer with no sectors sees nothing.
- **Sectors must not overlap.** `zone_of` files a report or detection under the *first* watch-zone polygon that contains it, so overlapping sectors make ownership arbitrary and silently order-dependent. Stated on the Sectors tab and in the new-sector dialog. Water outside every sector gets a null `zone_id` and is visible only to an admin, which is a deliberate, honest gap rather than a catch-all bucket.

- **`vessels_now` is counted, not stored.** It was a seeded field on `watch_zones` that nothing ever updated, and it was displayed in three places: the dashboard's "ships in zone now", the dashboard watch-zone grid, and the admin Sectors tab. It read 0 for the Dover Strait while the recorder held 189 real ships, and 61 for Gujarat which holds 8. `sectors.vessels_now(db)` now counts from the vessels themselves in one grouped query, using the same 2-hour freshness window as the Vessels page and the `vessels_tracked` KPI, so no two numbers on screen can disagree. Used by `/api/overview`, `/api/admin/zones` and the sector list.
- **Sample tiles belong to a sector, and the console shows the officer theirs.** Each entry in `SAMPLES` is stamped with the zone containing its footprint, `/api/detect/samples` is scoped by `zone_filter`, and the Detection Console lists only tiles for the region selected in the top bar, with an empty state that explains coverage is bundled per sector rather than showing a blank panel. A `?sample=` deep link still wins over the filter, so a link from the dashboard never lands on an empty console. The Gujarat sector was extended north to 22.8 N to take in the Gulf of Kutch, so Kandla, Mundra and the `kut-04` clean-sea tile sit inside a sector instead of unwatched water.

- **Motion is a shared vocabulary, not a per-component opinion.** `web/src/lib/motion.ts` holds the durations, easings and variants every animated component uses, reusing the curtain's own `[0.76, 0, 0.24, 1]` so a panel settling and a page arriving feel like the same hand moved them. Applied in `Primitives.tsx`, which is where the leverage is: `PageHeader` reveals eyebrow, title, description and actions in reading order; `Panel` and `KpiTile` reveal once as they scroll into view; `Button` gets press feedback. The nav's active pill is one element carried between tabs with `layoutId` rather than one fading out while another fades in. Only `transform` and `opacity` are animated, so nothing triggers layout, and motion clears the transform to `none` once settled, which matters because a lingering transform would make an ancestor a containing block and break the admin dialogs' `position: fixed`. Hover stays in CSS — a JS hover also fires on touch and sticks after the finger lifts — so the only pointer animation is a tap scale, which is honest on every input. `useReducedMotion` short-circuits every entrance to a plain static render, never a hidden initial state that could strand content invisible. Table rows are deliberately not animated: the Vessels page can render 2,000 of them. Verified by screenshot diff that the static UI is unchanged: the Reports page is pixel-identical and the others differ only in live "last login" timestamps and status dots.
